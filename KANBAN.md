# Kanban · patient-router

Доменная часть. Один пункт = один PR из своей ветки. Ничего не пишется в `main`
напрямую: только после зелёного CI (6 джобов).

## Правила

- Работа ведётся в **git worktree** — параллельные агенты не мешают друг другу.
- Ветка не удаляется после мержа: история сохраняется.
- `main` обновляется только merge-коммитом с пометкой, что проверки зелёные.
- Каждый пункт имеет критерий готовности, проверяемый тестом, а не «на глаз».

## Проверка «готово»

Для каждого пункта обязательны:

```bash
uv run ruff format --check .    # формат
uv run ruff check .             # линтер
uv run pytest                   # тесты
alembic check                   # схема совпадает с моделями
```

Плюс на GitHub: все 6 джобов зелёные (`Итог` — сводный).

## Известные риски

| Риск | Митигация |
|------|-----------|
| Декодер пишет сокомандник параллельно | Контракт зафиксирован в `base.py` + 29 тестов; его реализация должна пройти их без правок |
| Параллельные агенты правят общие файлы | Изоляция через worktree; общие файлы (`main.py`, `pyproject.toml`) правит только интегратор |
| Регрессия в объяснимости | `test_decision_engine.py` и `test_analysis_api.py` не должны меняться; их падение = блокер мержа |
