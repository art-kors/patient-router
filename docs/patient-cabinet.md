# Личный кабинет пациента

На главной странице нажмите демо-роль «Пациент». Демо-вход выдаёт существующий HMAC-токен с TTL и одной областью patient_ids. Для настроенных пользователей используйте логин и пароль; область кабинета берётся из AUTH_USERS. После входа открывается /patient. Кнопка «Выйти» удаляет токен сессии браузера.

Скрипт получает область через /api/v1/auth/me, затем читает /api/v1/mock/lk/{patient_id}/cabinet, /messages и /banner. Каталога и ввода идентификатора в кабинете нет. Общее серверное authorize проверяет patient_id в пути, запросе и теле, а также принадлежность route_id. Чужой пациент или маршрут возвращает 403; запрос без токена — 401. Чужое сообщение в своём кабинете — 404.

В кабинете четыре раздела с прямыми ссылками: протоколы, маршруты, уведомления и записи. Исследования показываются от новых к старым; находки и рекомендации берутся из связанных данных. Отсутствие протокола, находок или рекомендаций объясняется отдельно. Активные маршруты представлены отдельными карточками, завершённые — компактно под раскрытием. Внутренние статусы преобразуются на сервере через STAGE_TEXT, сведения о следующих шагах — через route_view.

Прочтение уведомления сохраняется существующим /messages/{message_id}/read. Отклики используют существующий /banner/{route_id}/response: confirmed_booking, cannot_attend и question. Первый требует реальной Appointment со статусом booked; остальные сохраняют ответ в аудите и создают задачу координатору. Они не отменяют приём и не создают запись. Старый wants_booking также передаёт просьбу координатору, без перехода в booked; already_attended сохраняет существующий переход по правилам автомата.

Раздел записей использует фактические Appointment, Followup, Hospitalization и Surgery. Рекомендованный контроль отличается от подтверждённого; плановое поступление не считается датой операции. Слоты не подбираются, отмена записи в интерфейсе не предлагается. При отсутствии факта записи кабинет предлагает связаться с клиникой.

Тексты вставляются через textContent, запрещённые формулировки скрываются только при отображении. Данные и обезличивание не меняются. Ресурсы локальные, без сборки и CDN; для чтения БД нужен локальный сервер. Проверки включают SQL-тесты принадлежности данных и Node с минимальным DOM для фактического вывода.

В исходной рабочей копии отсутствует app/services/anonymization.py, обязательный импорт существующего координатора. Этот файл не изменялся. До объединения с работой по обезличиванию полный запуск приложения и сбор полного набора тестов требуют восстановления этой зависимости.
