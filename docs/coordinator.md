# Рабочее место координатора

На `/` расположен общий вход. В сервисе `demo` жюри выбирает одну из шести
ролей и нажимает «Войти»: логин и временный пароль заполняются автоматически.
Пароль и ключ подписи генерируются в памяти процесса и в репозиторий не попадают.
Демо-вход открыт любому гостю и предназначен только для синтетических данных.
После перезапуска нужно войти заново. Демонстрационный сервер запускается одним
процессом, как в штатном compose.

В `prod`/`production` выдача демо-пароля отключена независимо от флага
`AUTH_DEMO_ENABLED`. Для закрытого стенда через окружение задаются `AUTH_SECRET`
и `AUTH_USERS`: JSON вида `логин → {role, password_hash, patient_ids}`.
`patient_ids` — список разрешённых UUID; пустой список не даёт доступа к пациентам.
Администратор имеет доступ ко всем пациентам. PBKDF2-хеш можно получить локально:

```bash
uv run python -c 'from getpass import getpass; from app.auth import password_hash; print(password_hash(getpass()))'
```

Храните результат и ключ вне Git. `.env` и `.env.*` игнорируются; `.env.example`
содержит только пустые поля авторизации. Подписанный HMAC-SHA256 токен живёт
`AUTH_TOKEN_TTL` секунд (по умолчанию час). Его срок проверяется по реальному
времени, независимо от перемотки модельных часов. Браузер хранит токен в
`sessionStorage` и передаёт как Bearer. Сервер возвращает 401 без действительного
токена и 403 при недостаточных правах. Страницы доступны как оболочки, данные API
защищены. Врач записывает решения, координатор работает со своей очередью,
менеджер госпитализации — со своими этапами, администратор — с настройками.

В демо очередь координатора включает синтетических пациентов файловой МИС и
созданных им обезличенных пациентов. Имена для поиска берутся из МИС: модель
`Patient` не хранит ФИО. Для иных пациентов показывается «Обезличенный пациент».
Поиск работает по ФИО демо-каталога, карте, UUID исследования и внешнему ID
исследования. Есть сортировка по имени/дате, счётчик и объяснение пустой выдачи.
Новый файл можно связать с выбранным пациентом или создать нового обезличенного.

Текстовый файл должен быть в UTF-8; повреждённая кодировка отклоняется.
Загрузка `.txt`/`.docx` сначала показывает все распознанные замены и весь
обезличенный текст. Учитываются также таблицы Word. ФИО, телефон, адрес, дата
рождения и номер карты заменяются пробелами той же длины. ФИО врача сохраняется по решению заказчика; дата приёма нужна для маршрута
и SLA и тоже сохраняется. Клинический текст сохраняет позиции символов.
Это ограниченные эвристики, поэтому оператор обязан проверить весь текст и
подтвердить отсутствие персональных данных. Без подтверждения запись в БД
не производится. Исходный файл и его имя не сохраняются. Предпросмотр действует
15 минут и подписан для конкретного пользователя; это отдельный билет,
который нельзя использовать как токен входа.

После подтверждения штатный `StudyProtocolSigned` создаёт Study, Protocol,
извлечённые Finding и срабатывания правил; применяются существующие правила
маршрутизации. Для нормы находки могут отсутствовать. Цитаты и абсолютные
смещения дополнительно проверяются перед коммитом: `text[start:end] == quote`.
Повторное подтверждение того же билета возвращает уже сохранённый документ.
Appointment при загрузке не создаётся: запись на приём остаётся реакцией на
`AppointmentBooked`, новых слотов нет.

`GET /api/v1/coordinator/patients/{patient_id}/protocols` возвращает все
исследования, протоколы, даты, типы, находки с цитатами и смещениями, применённые
правила с версиями и связанные маршруты, свежие сверху. Ограничения в десять
этапов старой карточки маршрута этот список не касаются. Каждый протокол
раскрывается клавиатурой в карточке пациента. Несуществующий пациент даёт 404,
пациент за пределами очереди — 403. Проверяется также выбор пациента при
сохранении, старые кабинеты, списки маршрутов/событий и каталог МИС.

Запрещённые медицинские формулировки маскируются только в отображении; цитаты
в API и БД остаются дословными. Исключение на экране врача — «Оперативное лечение
показано». Это ограничение языка интерфейса не меняет результаты извлечения.

Проверки: HTTP-тесты с реальными SQL-запросами на SQLite проверяют вход,
роли и область доступа, два формата файла, персональные данные в таблицах,
отсутствие записи до подтверждения, цитаты, полный список из 15 протоколов и
отсутствие Appointment. Node запускает целые скрипты с минимальным DOM и
проверяет реально отображённый текст, все протоколы и передачу Bearer-токена.
Стандартные тесты статики сохраняют проверки обхода пути и симлинков.
