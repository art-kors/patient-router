# Проверка схемы в CI

Smoke-джоба запускает `python -m scripts.check_schema` внутри контейнера приложения.
Ожидаемые имена таблиц берутся из `app.models.Base.metadata`; ожидаемое число —
размер этого множества. SQLAlchemy Inspector читает фактические таблицы схемы
`public`. Исключается только служебная `alembic_version`, которой нет в ORM.
Множества должны совпадать: даже подмена таблицы при прежнем количестве приводит
к коду завершения 1. Сообщение содержит ожидаемое и фактическое количество,
списки отсутствующих и лишних таблиц. Ошибки подключения также завершают процесс
с ошибкой. Ревизии отдельно проверяются миграциями и существующей проверкой готовности.

Python-модуль позволяет использовать одну проверку в контейнере и интеграционном
тесте миграций. YAML лишь запускает её, без копирования ожиданий ORM.

Саботаж в `tests/unit/test_ci_schema.py` меняет настоящий каталог SQLite:
удаляет `analysis_feedback`, добавляет лишнюю таблицу, заменяет одну другой
при неизменном количестве или удаляет все таблицы ORM. Каждый сценарий проверяет
исключение, диагностику и код 1 точки входа CI. SQLite здесь проверяет каталог
таблиц, а не PostgreSQL-типы; интеграционный тест проверяет реальные миграции
PostgreSQL через ту же функцию. Отдельный тест добавляет таблицу в метаданные:
проверка сначала падает, затем проходит после создания таблицы в БД.

Другие числа в workflow:

- `89` в проверке демо-сида заменено количеством `data/demo/protocols/*.txt`.
  Проверяются и протоколы, и исследования после двух запусков сида. Пустой набор
  считается ошибкой. Ограничение `89` снято и с самого сида, иначе рост набора
  продолжал бы ломать CI до проверки.
- `22` в вызываемом workflow интеграционном тесте заменено общей сверкой ORM.
- `20` и `30` попыток, пауза `2` секунды, параметры healthcheck `5s`/`10` —
  бюджеты ожидания готовности, а не количество сущностей проекта; оставлены.
- Порты, версии Python/UV/PostgreSQL/actions и срок хранения артефакта `7` дней —
  параметры окружения и хранения, а не хрупкие ожидания количества; оставлены.
- Проверок фиксированного количества эндпоинтов, миграций или файлов в YAML нет.
